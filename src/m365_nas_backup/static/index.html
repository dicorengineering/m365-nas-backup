Operation details


Before relying on this backup
This alpha still needs a live backup → delete → backup → restore test on your tenant. Retained snapshots cover email folders; online archives and other Microsoft 365 workloads are excluded.




Recover email
Choose a mailbox, browse its recovery points, then select messages to restore. Compare with the live mailbox when you need to see what changed.






Whole-mailbox recovery & export


Rebuild every backed-up email folder and message directly in an empty replacement mailbox. This uses the entire recovery point, regardless of search or message selection. Add the replacement address in Settings first.




The replacement must have a different mailbox identity and no existing email. Keep users and mail delivery out of it until recovery finishes. Contacts, calendars, rules and online archives are not included. Standard folders are mapped by identity; custom folders retain their hierarchy.




EML export requires portable copies saved with that recovery point (Settings). Older points without MIME can still be restored to Exchange. For classic Outlook bulk recovery, restore to the replacement mailbox, sync all mail, then use File → Open & Export → Import/Export → Export to a file → Outlook Data File (.pst). EML ZIP is not a PST.

Backup settings
Connect your tenant and choose how much history to keep.




Microsoft connection
Upload the public certificates to the matching Entra applications and grant the permissions listed in the setup guide. Private keys stay on this installation.


Certificate renewal
Certificates require an expiry date. Prepare a replacement, download it and upload it to the matching Microsoft Entra application, then test and activate it. The current certificate keeps working until activation.
365 days is the default. Longer local validity (up to 3,650 days) is only useful if Entra accepts it. Microsoft documents a one-year limit for adding credentials through Graph; tenant policies may also restrict duration. Verify the expiration shown in Entra after upload.


Mailboxes
Only these mailboxes are selected. An alias is not a separate mailbox. This installation connects to one tenant.


Version history
Shortening retention can permanently remove older recovery points. Increasing retention cannot recover history that has already been removed. At least the configured minimum is always retained.


Portable email copies
Optional: grant Microsoft Graph application Mail.Read to the backup app first, in addition to its existing permissions. The next successful backup captures portable copies of current messages, including unchanged ones; later backups reuse unchanged copies. This adds download time and storage. It cannot retrofit deleted or changed historical versions. A capture error fails that backup and keeps the previous completed recovery point.


Schedule and monitoring
The interval starts when the previous run finishes and survives restarts. Automatic monitoring allows an extra 50% of the interval (at least an hour) for the next run to finish. A custom overdue threshold must exceed the interval; otherwise automatic monitoring is used.





Console password
Use at least 12 characters. Changing the password signs out every browser session.


Retention cleanup
Review which expired recovery points would be removed before starting a manual cleanup.


Uptime Kuma
Add an HTTP monitor for /backup-status, accept status 200, and set the Authorization header to Bearer YOUR_MONITOR_TOKEN from monitor.token. The separate /health endpoint checks only whether the service is running.
